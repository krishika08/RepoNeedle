## 4. Zero-Oracle Runtime Policy

All algorithms implemented in R4 adhere to strict zero-oracle information boundaries:

1. **No Ground Truth Access**: Gold target file paths, labels, and relevance annotations are never accessed during indexing, tokenization, semantic projection, graph traversal, or scoring.
2. **No Metadata Leakage**: Benchmark query metadata fields (such as benchmark track labels: `trace2code`, `code2test`, `comment2context`, `edit2ripple`) are stripped prior to ranker invocation. Intent detection (e.g., test intent in Treatment E) operates purely via zero-shot regex and lexical pattern matching against the raw query string.
3. **No Repository-Specific Hardcoding**: All semantic embeddings, graph adjacency matrices, and feature weights are repository-agnostic. No rules matching specific repository names (e.g. `fastapi` or `clap-rs`) exist in the ranker logic.

## 5. Statistical Resampling Methodology

Because software engineering queries clustered within the same repository share common naming conventions, build tools, and directory topologies, standard query-level i.i.d. bootstrap resampling severely underestimates variance and produces anticonservative p-values.

### 5.1 Repository-Clustered Bootstrap
- **Bootstrap Unit**: Entire repository clusters ($K_{\text{val}} = 5$, $K_{\text{train}} = 15$, $K_{\text{held}} = 5$).
- **Iterations**: $B = 10,000$ resamples with replacement.
- **Metric Computation**: For each resample $b \in \{1, \dots, B\}$, all queries belonging to the sampled repositories are pooled, and the treatment MRR difference $\Delta^* = \text{MRR}_{\text{treatment}} - \text{MRR}_{\text{baseline}}$ is computed.
- **Empirical p-value**: $P^*(\Delta^* \le 0) = \frac{1}{B} \sum_{b=1}^B \mathbb{I}(\Delta^*_b \le 0)$.
- **Confidence Intervals**: 2.5th and 97.5th percentiles of the clustered bootstrap distribution.
