# 7. PHASE 3 — QUERY-CONDITIONED GRAPH PROPAGATION

Investigate query-conditioned graph retrieval.

The basic principle:

Only propagate structural relevance when the graph relationship is supported by the actual retrieval query.

A graph edge by itself should not guarantee relevance.

Inspect the existing architecture and choose an implementation compatible with its current score representation.

Potential query relevance signals:

- Lexical query-to-symbol overlap.
- Character/subword similarity.
- Query-to-path relevance.
- Identifier relevance.
- Initial lexical retrieval score.
- Structural relationship type.
- Node degree.

Do not introduce a pretrained neural model.

Do not assume these signals are equally important.

## 7.1 Query-conditioned backward propagation

Investigate whether high-relevance seed nodes can propagate scores backward to relevant callers, importers and integration contexts.

Use the existing hub-normalization mechanism as the initial reference.

A possible conceptual design:

1. Run lexical and subword retrieval.
2. Identify relevant initial seed nodes.
3. Measure the relevance of connected structural nodes to the query.
4. Apply backward propagation only when the relationship and query relevance justify it.
5. Normalize score contributions to avoid hub domination.
6. Combine graph contributions with the original retrieval score.

This is a research hypothesis, not a mandatory implementation specification.

Inspect the current graph direction conventions before coding.

## 7.2 Query-conditioned edge-type awareness

Investigate whether different relationships should receive different propagation eligibility.

For example:

- Importer relationships.
- Caller relationships.
- Module relationships.
- Entry-point relationships.
- Cross-crate dependencies.

Do not assume all edge types are equally valuable.

A relationship should contribute only when it provides evidence relevant to the actual query.

Test edge-type gating separately from other changes.

## 7.3 Degree-aware query-conditioned propagation

Investigate whether highly connected nodes should receive attenuated contributions depending on query relevance.

Preserve existing degree normalization as the baseline.

Avoid arbitrary penalties.

Any proposed normalization must have a clear mathematical explanation and controlled experiment.
