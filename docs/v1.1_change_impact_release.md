## 1. Release Highlights

RepoNeedle V1.1.0 introduces the **Change-Impact Ranking Engine**, an opt-in retrieval architecture engineered for software maintenance, bug fixing, and refactoring queries.

The engine computes seed-relative relationship scoring (incorporating static imports, symbol definitions, call sites, build manifests, test-stems, and directory proximity) relative to user-specified seed files, surfacing structurally coupled files that lexical and semantic search miss.

### Key Capabilities:
- **Statistically Verified Relevance Gain**: Delivers $+0.0288$ MRR improvement ($p = 0.0078$, 95% CI $[+0.0082, +0.0524]$) using repository-clustered statistical models across an independent cohort of 18 unseen open-source repositories ($N=180$ queries).
- **Strict Default Preservation**: The default ranking engine remains `legacy` (V1.0 behavior). Existing integrations experience zero behavior drift.
- **Fail-Safe Fallback**: If graph traversal encounters an unexpected exception, the engine automatically falls back to base lexical/semantic scoring without failing queries.
- **Verified CUD-Pack Invariants**: Strict non-exceedance of configured token budgets ($C_{\text{actual}} \le B_{\text{configured}}$) according to RepoNeedle's deterministic regex token model (`regex_code_tokenizer_v1`), verified across tested nominal budgets: 30, 50, 100, 500, 2000, and 4000 tokens.
- **Structured Explainability**: Every scored candidate provides structured attribution tracing which seed files and dependency edges contributed to its score.
- **Interactive Performance**: True end-to-end retrieval latency of **64.51 ms** (P50: 64.22 ms, P95: 67.32 ms) and peak RAM of **18.51 MB** on standard CPU hardware.

## 2. Quickstart & Usage Guide

### 2.1 Python API Usage

#### Seed-Based Change-Impact Retrieval:
```python
from reponeedle import RepoNeedleEngine, Query

# 1. Initialize engine with Change-Impact ranker
engine = RepoNeedleEngine.from_directory(
    repo_dir="./my-repo",
    ranker="change_impact",
)

# 2. Populate anchor_files with seed paths to activate relationship scoring
query = Query(
    text="Fix authentication session expiration",
    anchor_files=["auth/session.py"],
    budget_tokens=4000,
)

result = engine.retrieve(query)

# 3. Inspect selected files and relationship explanations
for item in result.selected_files:
    print(f"[{item.score:.3f}] {item.path} ({item.token_count} tokens, tier: {item.tier.value})")
    if item.explanation:
        print(f"       Attribution: {item.explanation}")
```

#### Query-Level Override:
```python
from reponeedle import RepoNeedleEngine, Query

# Leave default engine as legacy
engine = RepoNeedleEngine.from_directory(repo_dir="./my-repo")

# Opt in dynamically for change-aware queries
query = Query(
    text="refactor database connection pool",
    anchor_files=["db/pool.py"],
    budget_tokens=4000,
)

result = engine.retrieve(query, ranker="change_impact")
```

#### Advanced Tuning with `ChangeImpactConfig`:
```python
from reponeedle import RepoNeedleEngine, ChangeImpactConfig, Query

custom_config = ChangeImpactConfig(
    enable_graph=True,             # Enable seed-relative relationship scoring
    impact_multiplier=3.0,         # Multiplier for confirmed/heuristic impact
    sfs_multiplier=0.01,           # Seed File Suppression multiplier
    tip_multiplier_test=1.45,      # Test Intent Prior boost for test candidates
    tip_multiplier_non_test=0.85,  # Test Intent Prior penalty for non-test queries
    fallback_on_error=True,        # Fall back to base scoring on exception
)

engine = RepoNeedleEngine.from_directory(
    repo_dir="./my-repo",
    ranker="change_impact",
    change_impact_config=custom_config,
)
```

> [!NOTE]
> **Seed Path Population Requirement**: The Change-Impact ranking engine reads seed file paths from `query.anchor_files`. When `engine.retrieve(query)` is called with a plain string query, `anchor_files` is unpopulated, which skips seed-relative relationship scoring and applies only the Test Intent Prior (TIP). To activate seed-relative relationship scoring (imports, symbols, calls, manifests, test-stems, and directory proximity), pass seed paths via `Query(text=..., anchor_files=['path/to/seed.py'])`.

### 2.2 CLI Usage

The RepoNeedle CLI supports selecting the Change-Impact engine via the `--ranker` / `--ranking-engine` option:

```bash
# Standard query using default legacy ranker
reponeedle "refactor payment gateway in billing/stripe.py" --repo . --budget 4000

# Opt-in Change-Impact retrieval (applies Test Intent Prior scoring)
reponeedle "fix token expiration in auth/session.py" --repo . --budget 4000 --ranker change_impact

# Task-conditioned retrieval for finding regression tests
reponeedle "test suite for HTTPBasicAuth" --repo . --task code2test --budget 2000

# Packaged markdown output to a file
reponeedle "blueprints and route registration" --repo . --budget 4000 --output-file prompt.md
```

> [!NOTE]
> **CLI Seed-File Limitation**: The current CLI accepts query text as a positional string argument and does not currently expose a seed-file argument. Standard CLI queries run with `--ranker change_impact` apply Test Intent Prior scoring, while seed-based relationship scoring is available via the Python API (`Query(anchor_files=[...])`). CLI seed-file support is planned as a separate future enhancement.

If you observe unexpected candidate ordering on specific legacy queries, simply omit the `ranker` parameter or explicitly specify `ranker="legacy"`.

## 4. Benchmark Evidence & Evaluation Integrity

### 4.1 Independent R6 Cohort Benchmark Results

The Change-Impact engine was independently evaluated on an unseen cohort of 18 open-source repositories completely disjoint from the 25 historical ARB repositories.

Statistical inference was conducted using **repository-clustered statistical models** across independent repository clusters:

| Partition | Queries ($N$) | Repositories | Baseline MRR | Champion MRR | Delta (Δ) | Repository-Clustered Inference (95% CI) | Statistical Significance |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **Training** | $N=90$ | 9 repos | 0.6213 | 0.6546 | +0.0333 | — | Training fit |
| **Validation** | $N=40$ | 4 repos | 0.6472 | 0.6708 | +0.0236 | $p = 0.5073$, 95% CI [0.0000, +0.0472] | Not Statistically Significant |
| **Held-Out** | $N=50$ | 5 repos | 0.5215 | 0.5467 | +0.0252 | $p = 0.5025$, 95% CI [0.0000, +0.0629] | Not Statistically Significant |
| **Pooled Cohort** | $N=180$ | 18 repos | 0.5994 | **0.6282** | **+0.0288** | $p = 0.0078$, 95% CI [+0.0082, +0.0524] | **Statistically Significant ($p < 0.01$)** |

### 4.2 Candidate Pool & Metric Definitions
- **Pre-Filtered Candidate Pools**: Queries were evaluated against pre-filtered candidate pools averaging approximately **53.79 files per query**. Within these candidate pools, Candidate-Pool Recall@20 is 100%.
- **Whole-Repository Generalization**: Whole-repository Recall@20 of 60–75% represents a projected estimate under full repository indexing, not an empirically measured whole-codebase scan.
- **Statistical Power & Default Ranker**: While the pooled 18-repository cohort achieves statistically significant improvement under repository-clustered inference ($p = 0.0078$), the smaller isolated validation ($N=40$, $p = 0.5073$) and held-out ($N=50$, $p = 0.5025$) subsets are statistically underpowered. For this reason, the Change-Impact engine is provided as an **opt-in capability** rather than overriding the default `legacy` ranker.
- **Aspirational Research Target**: The long-term research objective of $\text{MRR} \ge 0.80$ is an aspirational research milestone, not an achieved production metric.

## 5. Performance & Operational Profile

Empirically profiled on standard multi-core CPU hardware (Windows 11 AMD64 & Linux x86_64):
- **True End-to-End Latency**: 64.51 ms (Mean), 64.22 ms (P50), 67.32 ms (P95).
- **Isolated Ranking Latency**: 20.28 ms (Mean), 20.08 ms (P50).
- **Index Construction (200 files)**: 852.07 ms.
- **Graph Construction Overhead**: 0.264 ms.
- **Incremental File Update**: 320.00 ms (via token and feature caching).
- **Peak RAM Overhead**: 18.51 MB.
- **Index Storage**: 35.38 KB.

## 6. Language Support & Fallback Boundaries

- **First-Class Typed AST Analysis**: Python, JavaScript/TypeScript, Go, Rust, Java, and C/C++.
- **Cargo Manifest Parsing**: Full TOML parser support on Python 3.11+ (`tomllib`) and Python 3.10 (`tomli>=2.0.1`), with zero-dependency regex fallback extracting package name, workspace members, and path dependencies.
- **Unrecognized File Types**: Gracefully fallback to directory proximity and lexical matching without raising exceptions.
- **Token Model Boundary**: Budget non-exceedance is enforced strictly according to RepoNeedle's internal regex token model (`regex_code_tokenizer_v1`). This does not imply exact token-count equivalence with arbitrary third-party LLM tokenizers or guarantee downstream token behavior for every provider.
